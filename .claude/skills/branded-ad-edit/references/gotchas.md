# Gotchas & working style

Every entry below cost real time on a proving run (#1–20 on a paid brand ad and a
style-clone reel, #21–30 on a product-news explainer built from a generated likeness). Skim before starting; return
whenever something looks wrong.

## The table

| # | Symptom | Cause | Fix |
|---|---|---|---|
| 1 | An element is BLACK/invisible during its early appearance, fine later | a LATER `fromTo(el, {opacity:0}, …)` stamps inline `opacity:0` at page load (`immediateRender` defaults true, even mid-timeline) and the early fade-in that would undo it was removed | `immediateRender: false` on the later fromTo. Tell: the element's own background doesn't paint — page backdrop shows through — so it's a stamped style, not media |
| 2 | Frame 0 shows the un-hidden state | `tl.set(..., 0)` doesn't render at playhead exactly 0 | initial hidden states in CSS (`opacity: 0` rule), animate in with fromTo |
| 3 | Motion stutters in renders | animating `top/left/width/height` (layout props snap to integer px under seek-capture) | transforms only: `x/y/scale/opacity` |
| 4 | A video renders FROZEN | `<video>` with `data-start` but no `id` | unique `id` on every media element |
| 5 | Video freezes under overlays on seeks | sparse GOP | re-encode ALL media `-g 30 -keyint_min 30` |
| 6 | A shortened variant renders full-length with a frozen tail | pretty-printed stage div splits attrs across lines; single-line attr regex missed `data-duration` | patch stage duration explicitly; ffprobe the RENDERED file, never trust the render log |
| 7 | SFX inaudible in the mix | ~1/3 of ElevenLabs sound-generations are near-silent; min duration 0.5s | volumedetect-audit every file; regenerate duds ("loud", "punchy", prompt_influence 0.6); normalize kit to −3dB |
| 8 | Music API 400 | artist name in prompt (ToS) | describe the style; the error body includes a `prompt_suggestion` |
| 9 | Two captions mashed on top of each other | a chunk held past the next chunk's start (long last word) | display window always ends at next chunk's raw start − 0.04 |
| 10 | Junk in B-roll frames (dialogs, widgets, personal windows) | Chrome-for-Testing keychain prompt (survives pkill as an orphan), chat widgets remounting | system Chrome + fresh userDataDir + `ignoreDefaultArgs:["--enable-automation"]`; sweep junk selectors on an interval; frame-extract-review EVERY take |
| 11 | Scripted scroll silently never moves | text-anchor matched an ancestor div whose top is 0 | target the SMALLEST matching node |
| 12 | Transcript oddities | last word ends past media end; brand names split into two words; hallucinated phrases on non-speech | clamp, merge (keep timestamps), null out Whisper-noise phrases |
| 13 | Missing glyph in renders | Apple private-use chars (, SF symbols) absent in headless Chrome | emoji or text labels |
| 14 | Overlap lint on an intentional stamp-over-content | two text blocks colliding | dim the underlayer to ~0.12 as the stamp lands — reads better anyway |
| 15 | `check` track-overlap errors in a cut variant | fully-cut cards left with stale times | excise their host blocks |
| 16 | Card text across the speaker's face | overlay card entering while a full-bleed segment still runs | delay the card to the framing cut; snapshot QA catches it |
| 17 | Consecutive `snapshot` calls leave only one frame | each call overwrites the output | ONE call with comma-separated `--at` list |
| 18 | A repeated take / false start survives into the edit but the transcript reads clean | **Whisper DEDUPES back-to-back retakes** on continuous audio — "and sub-agents your… and sub-agents your project…" transcribes as ONE slow phrase | transcribe silence-split segments in ISOLATION (per-clip, or concat with 1s silence separators); flag segments < ~1.6 words/sec and clip-transcribe those; ALSO re-transcribe the assembled master — each pass catches flubs the other hides |
| 19 | Karaoke captions drift late toward the back half ("captions are delayed") | Whisper on a full concatenated cut accumulates late drift — up to +1.1s by 70s, on every pass | never caption from whisper-on-the-cut: transcribe EVERY EDL window as an isolated clip and stitch word times through the EDL (`master = window.master_start + clip_time`) — frame-accurate; validate against `silencedetect` speech onsets |
| 20 | After a scripted retime, some animations fire at t=0 or wrong times | regex replacement callback args shift when a pattern has a NESTED capture group (the countUp bug: `parseFloat("\"#sel\"")` → NaN → mapped to 0) | count groups in every retime regex; remember positions NOT wrapped in `Q()`: helper call-sites (enter/exit/pop/rise/hide), wordSwap time arrays + endAt, countUp's at-arg, framing fns — enumerate all of them |
| 21 | **Every card square renders EMPTY** and `check` still passes with 0 errors | `class="clip"` + `data-start`/`data-duration` only *schedules* a host on its track — it does not clear the inline `visibility:hidden;opacity:0` you put on the host | give every card host an `enter()` (set visible + fromTo opacity) and `exit()` (to opacity 0 + set hidden) pair inside its clip window. The lint can't see this because the markup is valid; only a snapshot shows it |
| 22 | A control-render diff says most SFX are missing, but they're all there | the VO is loudness-normalised (−14 LUFS, peaks −1.2 dB), so a −13 dB hit can't move a window's peak *or* its 300ms RMS; and subtracting two AAC renders leaves the whole VO as residue, not the SFX | render a **SFX-only** take (`source-audio` and music `data-volume="0"`) and measure each hit window in that file — hits should land ~3–8 dB under the VO peak. Peak-diffing only works when the VO has headroom |
| 23 | The whole kit sits too quiet against the voice | the reference `data-volume` values assume a ~−7 dB VO | scale the kit to the VO you actually have (a −14 LUFS VO needed ×1.95, capped at 0.8) — decide this from a measurement, not from the reference numbers |
| 24 | A real page screenshot is unreadable inside a browser frame | on-canvas text size is `display_width ÷ css_width_of_the_crop`; capturing at 1440 and cropping barely helps | capture at a **narrow viewport (~620px)** so the page reflows to its mobile layout — the same text comes out ~1.5× larger on a 1080 canvas |
| 25 | Site B-roll looks soft or hitches on seek | it's a video, so it inherits GOP/seek problems and a re-encode generation | for page content, scroll a **tall PNG** inside the browser frame with a `y` tween instead. Sharper, perfectly deterministic, no keyframe concerns |
| 26 | A card element vanishes completely, no lint error | it's a sibling of `.sq` (which is `height:100%`), so it flows past the 1080 square and is clipped by the host's `overflow:hidden` | put it inside `.sq`, or make it `position:absolute` against `.root` |
| 27 | Card content clusters at the top with a dead void above the captions | `justify-content: flex-start` on the card stack | use `center` — opacity-0 elements still occupy layout, so nothing reflows as beats pop in |
| 28 | Two Whisper models disagree on a word | small vs medium hear it differently; you must not "fix" it by cutting or altering the speaker's audio | re-transcribe an **isolated 1–2s slice** with the bigger model; two of three agreeing decides the caption. Design the card around the accurate fact even when the caption keeps the speaker's wording |
| 29 | A build script dies `ENOENT` on a path containing `%20` | `new URL(import.meta.url).pathname` percent-encodes, and project paths often contain spaces | `fileURLToPath(import.meta.url)` |
| 30 | The delivered master clips — sample peak pinned at 0 dBFS, **true peak over 0 dBTP** | scaling the SFX kit up (gotcha 23) raises the SUM, and per-hit levels can all look right while the mix total goes over. AAC then overshoots the PCM peaks by another ~1.5 dB | after ANY level change, measure the render itself: `ffmpeg -i out.mp4 -af ebur128=peak=true -f null -`. Target ≈ −14 LUFS integrated and **≤ −1 dBTP**. Fix without re-rendering by mastering the audio and copying the video: `-c:v copy -af "aresample=192000,alimiter=limit=0.69:attack=1:release=40:level=disabled,aresample=48000" -c:a aac -b:a 192k`. Sweep the ceiling — the post-AAC true peak is what counts, not the limiter setting. Then confirm the limiter stayed transparent by re-measuring the SFX-only render through the same chain (should move ≤1 dB per hit) |
| 31 | A whole takeover scene is missing from the rendered MP4 (camera or blank shows instead), yet preview, `snapshot` and seeks all show it | HyperFrames' frame capture can drop a scene whose ENTRANCE moves the scene's own wrapper in from off-frame (a y/x push from ±1920, a rotationY card-flip, a whip-pan) — seen on several builds | Enter the scene with a hard `tl.set(wrapper, {opacity:1})` hidden under a separate covering element (a full-frame slab wiping across, a logo-square iris, a flash), then animate only the scene's CONTENTS. Proven to render: zoom-through, square iris, slats, spin-zoom, slab wipe, slide/push of inner content, and layouts built as transforms of ONE camera container (full frame → scaled card → corner bubble) over a static page, with no takeover clips at all. **Verify in the file, not the preview:** a flat-frame scan misses this when camera footage sits behind the scene, so pull MP4 frames at each takeover's midpoint and compare them to `snapshot` frames at the same times — any beat that differs wholesale is a drop Also seen on a small prop cover (a polaroid sliding in from `x:900`): it was in the preview and missing from every MP4 frame, while full-frame covers entering from off-frame rendered fine. An on-frame drop (`scale 1.7→1` after a hard opacity set) rendered. The v1 transition sheet missed it because the empty page under the missing prop looked like a clean swap: for a transition you designed, check that the *transition element itself* is visible in MP4 frames, not just that the swap is clean |
| 32 | A line-draw (`strokeDashoffset` tween) snaps from hidden to fully drawn halfway through instead of tracing | GSAP rounds the dash offset to whole units, and with `pathLength="1"` / `stroke-dasharray: 1` the only values left are 0 and 1 | Use `pathLength="1000"`, `stroke-dasharray: 1000; stroke-dashoffset: 1000` and tween 1000 → 0. Check one mid-draw frame from the MP4. A short 0.3 s tick hides the snap, but a 2 s chart line shows it |
| 33 | The reviewer calls the scene changes "glitchy" and "late, you can see the last frame from before" | Whole scenes were crossfaded. For ~8 frames both headlines and panels stack semi-transparently, and the old scene is still leaving after the new line has started. A pure fade-out then fade-in instead leaves 3–4 empty frames that QA flags as black | Swap on ONE frame, about 0.1 s before the word: `set(old, {opacity:0})` and `set(new, {opacity:1})` at the same time, and let only the new scene's transform or contents move in. For softer changes, do the swap under a full-frame cover (wipe, lift, iris) in the brand colour, not near-black, which QA reads as black frames. Check with a 14-frame strip around each change taken from the MP4 |
| 34 | Every segment after the first source switch is SILENT in the joined base (picture fine). Here it hit the owner's lines after a client clip. Neither QA nor the render flags it, because music and SFX still play over the gap | The parts were joined with the concat *demuxer* (`-f concat`) while their audio differed: phone takes in stereo, call recordings in mono. The demuxer assumes identical stream parameters and decodes the later segments as silence | Join mixed sources with ONE `concat` *filter*: every input goes through `aresample=48000,aformat=channel_layouts=stereo` and `setsar=1`. Then re-measure the speaker boundaries from the output, because the durations shift. Verify by measuring audio level per part in the joined base AND in the final MP4: any half-second below about −45 dB inside a spoken part is a failure. Also match LUFS per speaker; the phone mic sat about 5 dB under the call audio until boosted |
| 35 | Mid-session renders start failing, files come out truncated or missing, and even shell output is lost ("No space left on device") | HyperFrames caches extracted video frames in `/tmp/hyperframes-extract-cache-*` and never prunes it. After a few 16M PNG-frame renders of a 1080x1920 source it reaches about 20 GB and eats the session's disk allowance | After each delivered master, `rm -rf /tmp/hyperframes-extract-cache-0` (that path only; it is a cache) and delete the pre-mastering `out-*.mp4`. Check `df -h /` before a long render. If an output was written while the disk was full, re-render it; never ship it |
| 36 | Blocky macroblock smears on fast motion (a hand) in the base cut. The speaker is fine elsewhere, and the render passes every check | The jump-cut base was cut by seeking into a long-GOP / B-frame H.264 intermediate (`-ss` per input). ffmpeg logs "co located POCs unavailable", and frames after the seek point decode against missing references | Make the intermediate all-intra (`-g 1 -bf 0`, or ProRes), then cut from it. Gate the base with `ffmpeg -v error -i base.mp4 -f null -`: any decoder message is a failure. Spot-check a fast-motion frame against the source |
| 37 | A picture-in-picture `<video>` renders black in the MP4, though the preview looks fine | Several `<video>` elements share the same src/start/duration (e.g. three polaroids all playing `base.mp4`). The engine flags `duplicate_media_discovery_risk` and the duplicates come out black. Also, a voice-only upload has a black picture track, so a "talking head" window shows nothing anyway | One media element per src+window. For a face window, use a still frame (`ffmpeg -ss T -i talking.mp4 -frames:v 1`) or a separately cut clip with its own file. Check the source's picture (YAVG from `signalstats`) before planning any on-camera inserts |
| 38 | A 40s draft takes about 20 minutes, against the usual 3–5 | Seen while several `<video>` elements were present (see #37). Once they were replaced with stills, the same composition, SVG turbulence line boil included, captured 41s at delivery quality in about 3 minutes | When a render is suddenly slow, check for extra media elements first. Snapshot-verify, then render the master in the background. Don't blame filters without first bisecting |
| 39 | A graphic fires seconds early, or a panel ends before it starts and leaves an earlier card on screen | Single-word anchors (`/^For$/i`, `/^The$/i`, `/^If$/i`) match the first lowercase occurrence ("paid **for** which job", "**the** whole video", "**if** you're doing under") | Anchor every beat on a short exact PHRASE from the transcript ("For Joshua", "If it is for you"), then snapshot the whole video every ~6 s and confirm each beat lands on its line |
| 40 | Two full-frame graphics back to back: the second one plays on black, and the camera bubble zooms out and back | The first takeover's exit (fade the paper, return the camera) overlaps the second takeover's entrance on the same elements | Schedule layouts together: neighbours of the same kind (takeover→takeover, panel→panel) chain, so the paper/bubble/camera stay put and only the content swaps |
| 41 | A render dies with ENOENT on `__hyperframes_video_frames/.../frame_00001.png`, or captureScreenshot fails | The shared frame cache (`/tmp/hyperframes-extract-cache-0`) was deleted while another render or snapshot was still reading it (or the disk filled mid-render) | Run one render at a time; clear the cache only after that render finishes; keep several GB free before a long landscape render |
| 42 | Captions show "$2 ,250", "10 %", "$1 ,165." | The transcriber splits numbers into tokens | Re-join tokens that start with ",digit", "%" or ".digit" onto the previous number when loading words |
| 43 | A cut drops or doubles words ("$1,165" becomes "$1,000"; "answer a couple quick… answer a couple quick") | Word timestamps from the full take drift around retakes and stutters, so windows end mid-word or include a false start | Move cut edges onto measured silence (10 ms RMS), squeeze long pauses, re-transcribe the CUT audio, and read it against the script before the slow passes (blur, render); for a retake that runs straight on, word-time just that 15 s with a fresh pass and hard-cut at the word |
| 44 | A screen recording for a "demo" shows a real client's CRM (customer names, job values, pipeline name) | It was recorded on a live account | Never publish it as is: rebuild the board as an animated replica with made-up names and keep the speaker in a face bubble, or blur every name; say so in the delivery |
| 45 | The reviewer says the cut is slow: a pause before every line, a restart left in, a spoken "cut" audible, a last word clipped | The speaker was reading a script. The cut used word windows from a whole-take transcript, which merges a false start into its retake, and its timestamps drift at stutters, so windows end mid-word | Cut at the utterance level with `tools/uttercut`. Split at pauses ≥ 0.3 s, transcribe each utterance alone, keep one clean read per line (anything before a spoken "cut" goes), butt pieces with no gap, and keep each piece's natural tail. Then run `tcheck.py` and `headchk.py` on every flagged edge. |
| 46 | The same sound effect is heard twice in a row, or in nearly every scene | Each beat hard-codes a sound name, and the pool's pitch variants (`@lo`/`@hi`) count as different sounds | Assign SFX at write time from category pools in least-recently-used order: distinct sounds first, variants last, at least 0.7 s apart. Audit the pool for near-silent duds before use. |
| 47 | A b-roll insert turns the rest of the video black | The insert's end anchor matched a word before its start anchor, so the span was negative and the clip never ended | Anchor on phrases, not single words. Make the insert helper throw when `end <= start + 0.6`. |
| 48 | A finished long video will not send to the reviewer | The file is over the delivery channel's upload cap (seen at 400–500 MiB; read the limit the tool reports) at a 16M master bitrate | Keep the master. Make a separate delivery copy re-encoded to about 95% of the cap (two-pass or a computed bitrate), verify that copy, and send it. |
| 49 | An uploaded clip plays as a black screen with normal audio; every frame extract is black | The upload path transcoded an HDR phone clip and lost the picture (8-bit, HLG tag, a few hundred kbps) | Probe mean luma (`signalstats` YAVG ≈ 16 means black) right after ffprobe. Ask for the original file, and keep working on everything keyed to the audio (cut, captions, graphics, sound) meanwhile. |
| 50 | The speaker must sit between a "behind" layer and a "front" layer of HTML graphics, and the renderer has no alpha video | A normal `<video>` is opaque, and a transformed wrapper isolates blend modes | Use `tools/bgmatte/cutout.py`: a multiply matte video plus a premultiplied add video, stacked as siblings of the graphics. Transform both with the same tween. |
| 51 | The first full build was thrown away: the reviewer wanted no face at all | "Motion graphic type of video" was read as "talking head with heavy graphics" because footage of the speaker was attached | When a brief says motion graphic / explainer / animation, confirm face or faceless before building the speaker pipeline. A recording of the speaker may only be the voice-over. |
| 52 | A faceless render shows a near-empty frame for a quarter second at each colour wipe | The outgoing scene was faded out before the wipe began, and the incoming one starts after it ends | Keep the outgoing scene visible until the wipe is crossing it (fade at wipe start + 0.1 s) and land the first incoming element by the wipe's end. Check frames at wipe midpoints in the rendered file. |
| 53 | Sentences are cut correctly but there is still about 0.7 s of dead air at every join | The take's room tone sits above the splitter's low threshold, so each utterance carries up to 0.3 s of noise on both sides | Tighten each piece to the voice with a threshold set from the room tone between utterances (`cut.py` now does this), then scan the cut for silences over 0.2 s. A fixed level relative to the take's p90 is not enough when silence makes up half the take. |
| 54 | A proof screenshot cannot be captured: the site is blocked from the build machine | The egress policy refuses the host, so a local browser gets a tunnel error | Capture it through a hosted scrape tool's screenshot output, crop the sentence, and pair the crop with a re-typeset pull-quote, because a narrow table column upscaled to video width is too soft to read on its own. |

## Working style that made the proving run work

- **Verify pixels and dB, not intentions.** Extract frames / snapshot contact sheets
  and look with vision; measure audio windows with volumedetect against a baseline
  render. Every bug above was caught that way — none by re-reading code.
- **Generate the repetitive 90%** (caption spans/tweens, SFX elements, EDL remaps)
  from the transcript with a build script; hand-author only the cards, where design
  judgment lives. Template + generator also makes every revision a cheap
  regenerate-and-re-render.
- **Bisect with the cheapest tool.** snapshot (~30s) before render (~3min). The
  immediateRender bug survived three renders and fell to a snapshot loop in minutes.
- **Ask preferences once** (ratio, layout mix, variants), then run autonomously to a
  reviewable draft. Deliver drafts; incorporate redirects.
- **Never overwrite an approved cut** — new versions are new files.
- **Real brand assets over recreations**, always.
- **Timestamped review beats prose feedback.** A frame.io-style review page (video +
  scrubber + pinned comments the agent reads back via API) turned vague notes into
  surgical fixes — 20 timestamped comments across two rounds, every one actionable.
